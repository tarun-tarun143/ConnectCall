# ConnectCall

**Connect with anyone, anywhere.**

A production-oriented Flutter internship assignment implementation using **Firebase Authentication + Cloud Firestore + Firebase Cloud Messaging + ZEGOCLOUD Call Kit**. The project targets the required 1-to-1 audio/video calling flow, incoming calls, accept/reject, mute, camera controls, call history, permissions, error handling, and the bonus features that make sense for an internship submission.

## What changed in this release

The previous LiveKit implementation has been removed. ConnectCall now uses the ZEGOCLOUD Flutter Call Kit and signaling plugin end-to-end. ZEGOCLOUD's current Flutter Call Kit package provides 1-to-1 and group voice/video calls, call invitations, offline invitations, device management, customizable UI, missed calls, screen sharing, and related call controls. The project pins `zego_uikit_prebuilt_call: ^4.24.4` and `zego_uikit_signaling_plugin: ^2.8.21` for the September 2026 environment.

## Included functionality

- Firebase email/password registration, login, password reset and logout
- User profiles with online presence, username, phone, bio and optional photo URL
- Contact list and search by name, username, email or phone
- One-tap 1-to-1 audio/video call invitations
- Incoming call UI from ZEGOCLOUD Call Kit
- Accept/reject/cancel/timeout flows handled by the Call Kit
- Microphone mute/unmute and camera on/off/switch controls inside the call UI
- Call history stored in Firestore
- Missed/busy/rejected/failed/disconnected status model
- Network availability guard before starting a call
- Permission handling for microphone, camera and notifications
- Dark/light/system theme
- Blocked-user data model and screens
- Favorites and online presence fields
- Group calling flow with up to 4 selected participants in the app UI
- Screen sharing support through ZEGOCLOUD Call Kit capabilities
- FCM token registration for the optional app backend notification endpoint
- Backend health endpoint and optional FCM multicast sender

## Why ZEGOCLOUD

The internship assignment explicitly allows ZEGOCLOUD, and its Flutter Call Kit provides the calling and invitation business logic that the assignment evaluates. This reduces custom WebRTC signaling code while leaving the rest of the product architecture under our control.

Open **Android Studio → Open** and select the project folder.


Run on a real Android device for calling tests. ZEGOCLOUD documents that offline-call invitation testing should be done on physical devices rather than relying only on simulators.

## Required configuration

The source code intentionally does not contain your ZEGOCLOUD AppSign or Firebase credentials. Use Android Studio Terminal and pass them as Dart defines.

You already created this ZEGOCLOUD project:

- Project: `ConnectCall`
- AppID: `503220443`

From the ZEGOCLOUD Console, copy the **AppSign** but do not publish the **ServerSecret** or **CallbackSecret**. AppSign is supplied to the Flutter Call Kit; ServerSecret is not used by this app.

Configure Firebase Authentication and Firestore, then use:

```bash
flutter run \
  --dart-define=ZEGO_APP_ID=503220443 \
  --dart-define=ZEGO_APP_SIGN="YOUR_APPSIGN" \
  --dart-define=FIREBASE_API_KEY="YOUR_FIREBASE_API_KEY" \
  --dart-define=FIREBASE_APP_ID="YOUR_FIREBASE_APP_ID" \
  --dart-define=FIREBASE_MESSAGING_SENDER_ID="YOUR_SENDER_ID" \
  --dart-define=FIREBASE_PROJECT_ID="YOUR_PROJECT_ID" \
  --dart-define=FIREBASE_STORAGE_BUCKET="YOUR_BUCKET"
```

For a release build, keep the secrets out of git and configure them through your build/CI secret mechanism.

## ZEGOCLOUD call invitation setup

ZEGOCLOUD's Flutter invitation guide requires the Call Kit invitation service to be initialized after the app user logs in, a navigator key registered with the service, and the signaling plugin provided to the service. This project follows that pattern.

For **offline call invitations / system calling UI**, complete the Android Firebase and ZEGOCLOUD console configuration described by ZEGOCLOUD's current Call Kit invitation guide. In particular, configure the push resource ID in the ZEGOCLOUD console and use the same resource ID in the call-invitation settings when you enable offline notification behavior.

The in-app call invitation works without a separate calling server owned by the project. The ZEGOCLOUD Call Kit and signaling plugin handle the realtime calling UI and invitation flow.

## Backend

The backend is optional for normal ZEGOCLOUD calling. It exists for the internship project's backend-integration story and optional Firebase Admin notifications.

```bash
cd backend
npm install
npm start
```

Health check:

```bash

```

```json
{"ok":true,"service":"connectcall-backend","firebaseAdmin":false}
```

To enable the optional Firebase Admin notification endpoint, copy `.env.example` to `.env` and provide a Firebase service account configuration.

## Two-device demo

1. Create two Firebase accounts.
2. Install the APK on two Android phones.
3. Sign in as user A on phone 1 and user B on phone 2.
4. Wait until both profiles show online.
5. From A, start an audio or video call to B.
6. Accept the call on B.
7. Verify mute/unmute, speaker, camera, front/rear switch and end call.
8. Repeat with video.
9. Verify call history on both devices.
10. Test reject, timeout, offline and permission-denied cases.

## Security

- Do not commit ZEGOCLOUD ServerSecret or CallbackSecret.
- Do not put Firebase Admin private keys in Flutter.
- Use Firestore Security Rules for access control.
- Use HTTPS for any public backend.
- Add authentication/rate limiting before exposing the optional backend to the internet.
- Do not claim call recording is implemented until provider/platform support, consent, retention and secure storage are configured.
